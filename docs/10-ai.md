# AI Chat

`TechnyxSdk.Ai` (`AiService`): a chat with the Technyx assistant, either as one answer or as a stream, plus the stored conversations of the signed-in user. Every call returns `ApiResponse<T>` (see [HTTP Client](05-http-client.md)) and takes an optional `CancellationToken`.

> **Availability:** the AI module lives in the backend branch `feature/BE-215--ai-module`. At the time of writing the deployed backend image does not contain it, so `/ai/*` answers `404` there. The SDK follows the code of that branch and has not been run against a live AI endpoint.

## Knowledge items

The assistant does not search the knowledge base itself. The client retrieves passages (for example from the Qdrant `aviation_manuals` collection) and sends them as `KnowledgeContext`; the backend passes them to the model and reports which of them the answer rests on.

```csharp
using Technyx.Sdk;
using Technyx.Sdk.Models;

var request = new AiChatRequest
{
    Message = "What is the torque for the propeller bolts?",      // required, at most 5000 characters
    Language = LanguageCodes.English,                              // sk, en or cs; Slovak when omitted
    ConversationId = conversationId,                               // continue an existing, active conversation
    Context = new AiChatContext { TaskId = taskUlid, Location = "Hangar 2" },
    KnowledgeContext = new List<AiKnowledgeItem>
    {
        new AiKnowledgeItem
        {
            SourceId = "doc-17-p6",        // required
            SourceType = "manual",         // required
            Title = "AMM 61-10",           // required
            Content = "Torque 25 Nm ...",  // required, at most 10000 characters
            RelevanceScore = 0.91,         // optional, 0 to 1
            DocumentMeta = new AiDocumentMeta { Filename = "DA201-A1.pdf", Pages = new List<int> { 6, 7 } },
        },
    },
};
```

Fields that are not set are not sent (the backend rejects explicit `null`s).

## One answer

```csharp
var response = await TechnyxSdk.Ai.ChatAsync(request);
if (response.IsSuccess)
{
    Debug.Log(response.Data.Message.Content);
    var conversationId = response.Data.Conversation.Id;   // pass it back to continue
}
```

The call returns when the whole answer exists and runs under `streamTimeoutSeconds` (300 s by default). The backend handles it synchronously, so it holds a server worker for the duration of the model call – prefer the stream for anything interactive.

`AiChatResult` has `Message` (`AiMessageData`) and `Conversation` (`AiConversationRef`: `Id`, `Title`, `MessagesCount`).

## Stream

```csharp
var sb = new StringBuilder();

var response = await TechnyxSdk.Ai.ChatStreamAsync(
    request,
    onChunk: chunk => { sb.Append(chunk.Text); label.text = sb.ToString(); },
    onSource: source => Debug.Log($"Source {source.Title} ({source.RelevanceScore})"),
    cancellationToken: cts.Token);

if (response.IsSuccess)
{
    var done = response.Data;   // AiStreamDone
    Debug.Log($"{done.Tokens.Output} tokens, {done.LatencyMs} ms, conversation {done.ConversationId}");
}
else if (response.Error.Code == "AI_RATE_LIMIT")
{
    ShowRetryIn(response.Error.RetryAfterSeconds);
}
```

The transport is Server-Sent Events over a `POST` (`ai/chat/stream`), read incrementally. The backend sends:

| Event | Payload | SDK type | Notes |
|-------|---------|----------|-------|
| `chunk` | `text`, `index` | `AiStreamChunk` | the answer in order |
| `source` | `source_id`, `title`, `relevance_score`, `document_meta` | `AiStreamSource` | sent **after** the last chunk, not next to the passage that uses it |
| `done` | `message_ulid`, `conversation_ulid`, `grounding`, `sources`, `tokens`, `cost_cents`, `provider`, `model`, `latency_ms` | `AiStreamDone` | closes a successful stream |
| `error` | `message`, `code` (`STREAM_ERROR`) | – | the call fails with that code and message |

Rules of the result:

- `IsSuccess` is `true` only when `done` arrived. A stream that ends without it fails with `STREAM_INTERRUPTED`; chunks that were already delivered to `onChunk` stay delivered, so keep what you showed or discard it deliberately.
- Failures before the stream starts (rate limit, budget, validation, missing organization) arrive as an ordinary error response with the backend's code, `Message`, `Details` and `RetryAfterSeconds`.
- A malformed event ends the call with `PARSE_ERROR`; no further chunks are delivered after it.
- Unknown events and `:` comment lines are ignored.
- An exception thrown by `onChunk` or `onSource` is logged with `Debug.LogException` and does not stop the stream.
- `onChunk` and `onSource` run on the thread on which Unity delivers the download data. That has not been verified in a real player; if you touch Unity objects, check it or hand the work to the main thread.
- A stream is never repeated after a transport failure (only after a `429`, before it starts), because chunks may already have been shown.
- Cancelling stops reading; the call returns `IsCancelled`. Whether the backend keeps generating after the client disconnected is not known.
- `RawBody` of a streamed response holds only its first 64 KB.

## Errors specific to AI

| Code | Status | Meaning |
|------|--------|---------|
| `AI_RATE_LIMIT` | 429 | Too many requests. `RetryAfterSeconds` says how long to wait. The client already waits and retries up to `maxRetries` times when that is at most `maxRetryDelaySeconds`. |
| `AI_BUDGET_EXCEEDED` | 403 | The organization's budget is used up. `Details` has `budget_cents`, `used_cents` and `resets_at`. |
| `AI_NO_ORGANIZATION` | 403 | The user has no organization. |
| `VALIDATION_ERROR` | 422 | For example `conversation_ulid`: the conversation is unknown, belongs to someone else or is not active. Read `GetFieldErrors("conversation_ulid")`. |
| `STREAM_ERROR` / `STREAM_INTERRUPTED` | – | Failures inside a stream, see above. |

## Grounding and sources

An answer carries `Grounding` (`AiGroundingData`):

- `GroundedRatio` – share of the answer backed by a knowledge item, 0 to 1.
- `GroundedSegments` – passages with the `SourceId` they come from and its `DocumentMeta`.
- `GeneratedSegments` – passages written by the model without a source, each with a `Confidence`.

`Confidence` is a **string** (`AiConfidence.High`, `Medium`, `Low`), not a number. `Sources` (`AiSourceData`) echo the knowledge items you sent, with `Referenced` set when the answer uses them. `DocumentMeta` is a `JToken` because the backend stores whatever the client sent.

## Conversations

```csharp
// List, newest activity first. Filters are optional; page size is up to 50.
var list = await TechnyxSdk.Ai.ListConversationsAsync(
    status: AiConversationStatus.Active,
    createdFrom: DateTimeOffset.UtcNow.AddDays(-30));

// Messages, oldest first, 50 per page by default (up to 100)
var detail = await TechnyxSdk.Ai.GetConversationAsync(conversationId, page: 1, perPage: 50);
if (detail.Data.MessagesMeta.HasMore) { /* request page 2 */ }

// Rename or archive
await TechnyxSdk.Ai.UpdateConversationAsync(conversationId, new UpdateAiConversationRequest
{
    Title = "Propeller torque",
    Status = AiConversationStatus.Archived,
});

await TechnyxSdk.Ai.DeleteConversationAsync(conversationId);
```

- `AiConversationStatus`: `Active`, `Closed`, `Archived`. Only an active conversation accepts new messages.
- The date filters are sent as UTC (`yyyy-MM-dd HH:mm:ss`); the backend compares the string with its UTC `created_at`.
- `AiConversationData` (list and update): `Id`, `Title`, `Status`, `Language`, `MessagesCount`, `LastMessage` (`Role`, `Content` shortened to 200 characters, `CreatedAt`; `null` without messages), `CreatedAt`, `UpdatedAt`.
- `AiConversationDetail` (single conversation): the fields above plus `Context` and `Messages` (`List<AiMessageData>`) with `MessagesMeta` (`CurrentPage`, `PerPage`, `Total`, `HasMore`). Unlike other collections, the messages are paged without a `last_page`. The backend may send an empty `Context` as `[]`, hence `Context` is a `JToken`.
- `AiMessageData`: `Id`, `Role` (`user` or `assistant`), `Content`, `Sources`, `Grounding`, `Provider`, `Model`, `Tokens`, `AudioUrl`, `CreatedAt`. `Provider`, `Model` and `Tokens` are only present on assistant messages.
